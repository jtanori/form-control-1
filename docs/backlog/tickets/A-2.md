## Summary

The "Eyes", part 2: turn each discovered element into a **human-readable description** the LLM can reason about. Real forms are labelled with `<label>`, `aria-label`, `aria-labelledby`, `<legend>`, placeholders, nearby headings — or nothing at all. This ticket implements the deterministic waterfall that produces `label`, `groupLabel`, and `validationError`.

Without this ticket the Brain sees `input#txt_9f3a` and cannot map *"my email is…"* to a field.

## Public API

```ts
// packages/dom-engine/src/eyes/labels.ts
export interface ResolvedContext {
  label: string;                 // never empty; falls back to a readable token
  labelSource: LabelSource;      // 'aria-label' | 'aria-labelledby' | 'label-for' | 'label-parent'
                                 // | 'proximity' | 'placeholder' | 'name-attr' | 'fallback'
  groupLabel?: string;
  validationError?: string;
  required: boolean;
  requiredSource: 'html' | 'aria' | 'label-marker' | 'none';
}

export function resolveContext(el: HTMLElement): ResolvedContext;

export type LabelSource =
  | 'aria-label' | 'aria-labelledby' | 'label-for' | 'label-parent'
  | 'proximity' | 'placeholder' | 'name-attr' | 'fallback';
```

Results are cached per element in a `WeakMap` for the duration of one distillation pass (`clearContextCache()` exported for tests).

## Label waterfall (execute in order, stop at first non-empty result)

### Step 1 — `aria-label`

```ts
const v = el.getAttribute('aria-label')?.trim();
if (v) return v;
```

### Step 2 — `aria-labelledby`

- Split `aria-labelledby` on whitespace.
- Resolve each ID **within the element's root node first** (`el.getRootNode().getElementById?.(id)`), then fall back to `document.getElementById(id)` (needed when a shadow-DOM element points at a light-DOM label and vice-versa).
- Concatenate with a single space, join non-empty texts, preserve order.
- If the referenced node is itself an input, use its resolved label (depth ≤ 2, guard against cycles with a `Set<Element>`).

### Step 3 — explicit `<label for="…">`

- Requires `el.id`. Escape the ID: `CSS.escape(el.id)`.
- Search in the element's root node **and** in the document (labels are frequently outside the shadow root).
- Multiple labels: join with a space.
- Extract text with the normaliser (below), which also strips any nested control text.

### Step 4 — implicit parent `<label>`

```ts
const label = el.closest('label');
if (label) {
  const clone = label.cloneNode(true) as HTMLElement;
  clone.querySelectorAll('input, select, textarea, button, [role=button], svg').forEach(n => n.remove());
  return normalise(clone.innerText || clone.textContent);
}
```

Cloning is mandatory: `innerText` on the live node includes the checkbox's own rendered text in some browsers, and reading `innerText` forces layout.

### Step 5 — proximity heuristic

- Candidate A: `el.previousElementSibling`.
- Candidate B: parent's `previousElementSibling` (handles `<div class="row"><div class="label">…</div><div class="input"><input></div></div>`).
- Candidate C: first child element of the closest "field wrapper" (parent up to 2 levels) whose tag is `label, span, div, p, h1-h6` **and** which contains no interactive control.
- Accept a candidate only if: visible, its normalised text is `1..60` characters, it contains **no** form control, and it is not already used as the label of a sibling control (avoid giving two inputs the same "Email" text from one shared header — track used text per pass).
- Strip trailing `:` / `*` / `(required)` via the normaliser.

### Step 6 — fallbacks

1. `placeholder` (trimmed, colon-stripped).
2. `name` → humanise: `billing_address_line1` → `Billing Address Line 1`, `firstName` → `First Name`, strip `input-`/`field-`/`txt-` prefixes and trailing digits.
3. `data-testid` (same humanisation).
4. `id` (same humanisation).
5. `'Field'` — never empty; the Brain must always have something to reason about.

### Normaliser (used everywhere)

```ts
function normalise(raw: string | null | undefined): string {
  return (raw ?? '')
    .replace(/\s+/g, ' ')                      // collapse whitespace incl. newlines
    .replace(/[*✱]/g, '')                      // required asterisks
    .replace(/\s*[:(]\s*required\s*\)?\s*$/i, '') // "(required)" / ": required"
    .replace(/\s*:+\s*$/, '')                  // trailing colon
    .replace(/^required\s+/i, '')
    .trim()
    .slice(0, 120);
}
```

Also strip visually-hidden helper text that libraries inject (`"Required"`, `"*"`, zero-width space `\u200B`) and emoji.

## Group label resolution

1. Nearest ancestor `<fieldset>` → its first `<legend>` text (normalised). Cross shadow boundaries with the `parentOf` helper from A-1.
2. Else nearest ancestor `[role="group"]` / `[role="radiogroup"]` with `aria-label`/`aria-labelledby`.
3. Else walk **backwards** from the element up to 6 ancestor levels: check the element's own previous siblings, then each ancestor's previous siblings, for a heading (`h1..h6`, `[role=heading]`) or a bare text block `< 80` chars that is not a label. Stop at the nearest `<form>`/`<section>`/`<main>` boundary.
4. Else the closest `<section>`/`<form>` with `aria-label` or `aria-labelledby`.
5. Else `undefined` (do **not** invent a group label; the Brain must see ambiguity).

Group labels are cached per container element because they are expensive to recompute for 40 inputs.

## Validation error resolution

Only report an error that the **user can currently see**:

1. If `aria-invalid="true"` **and** `aria-errormessage` points to a node → its normalised text.
2. If `aria-invalid="true"` **and** `aria-describedby` → concatenate referenced nodes whose text matches an error-ish pattern (`/error|invalid|required|must|can't|cannot|enter|valid/i`) or whose element has `role="alert"`.
3. Nearest `[role="alert"]` inside the field wrapper (parent up to 3 levels) → its text.
4. Sibling/descendant node of the field wrapper whose `class` or `id` matches `/(error|invalid|danger|feedback|helper-error|text-red)/i` **and** has non-empty visible text `< 200` chars.
5. Computed colour heuristic: the node's `color` is "red-ish" (`r > 140 && r > g * 1.6 && r > b * 1.6`), it is visible, and its text is `< 200` chars.
6. HTML5 constraint validation as last resort: if `el.matches(':invalid')` **and** the element has been interacted with (`el.dataset.vfeTouched === 'true'` set by B-1) **and** `(el as HTMLInputElement).validationMessage` is non-empty → that message (browser-localised).

Rules:
- Maximum one error string per element; prefer the closest match in DOM order.
- Ignore placeholder-ish helper text (`"We'll never share your email"`) unless it matches `role=alert` or an error class.
- Never throw: any DOM exception inside resolution returns `undefined`.

## Integration with A-1

A-1 already excluded invisible elements. A-2 must still be defensive: `resolveContext` may be called on a hidden node (e.g. after a re-render race) and must not return text from a `display:none` helper.

## Radio/checkbox specifics

- A radio input's `label` is its own visible option text (`"Standard shipping"`), and `groupLabel` is the fieldset legend (`"Shipping method"`).
- A checkbox group ("Interests") with 5 checkboxes yields 5 elements sharing `groupLabel`, each with its own label.
- `<select>` `label` is the control label; option texts are serialised by A-3.

### Required-field detection

`required` = `el.required === true` **or** `aria-required="true"` **or** the resolved label text matched a `*`/`(required)` marker (marker stripped from `label`). `requiredSource` reports which. `aria-invalid` alone is not `required`.

## Acceptance criteria

- [ ] All 15 fixture rows pass with exact expected values (no regex fuzz in assertions).
- [ ] Waterfall order is enforced by tests: e.g. `aria-label-wins.html` proves step 1 beats step 3.
- [ ] Label is **never** an empty string for any discovered element.
- [ ] Every result reports a `labelSource`; no result falls to `'Field'` in any of the 15 fixtures.
- [ ] `groupLabel` is correct for fieldsets, radiogroups, and heading sections; `undefined` when genuinely absent.
- [ ] `validationError` is only returned for visible messages; hidden `.error` templates are ignored.
- [ ] Cross-shadow-boundary label resolution works in Chromium (Playwright) and in jsdom.
- [ ] Resolution of 250 elements < 15 ms (benchmark test, CI ×3).
- [ ] No `innerText` reads on hidden/detached nodes (spy assertion in tests).
- [ ] Coverage ≥ 95% on `labels.ts`, `group.ts`, `errors.ts`.

## Non-goals

- Translating labels.
- OCR of labels rendered in images/canvas.
- Inferring semantic meaning ("is this a first name?") — that is the Brain's job; A-2 only reports what the page says.
- Detecting errors that appear only after submit *in this ticket* — INT-2 handles the post-submit diff, A-2 just reads the resulting DOM.
