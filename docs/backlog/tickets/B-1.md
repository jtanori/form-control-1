## Summary

The "Hands", part 1: make `FILL` and `CLEAR` actually work. React 16+, Vue, Angular, Svelte and every controlled component track input state through patched property setters and event listeners. Writing `el.value = 'foo'` sets the DOM but leaves framework state stale — the form then submits empty data, or the framework re-renders and wipes the value on the next keystroke.

This ticket implements the native-setter bypass plus a full, correctly-ordered event sequence that satisfies controlled components, `onChange` handlers, validation libraries, and IME-sensitive widgets.

## Public API

```ts
// packages/dom-engine/src/hands/fill.ts
export interface FillOptions {
  /** Scroll into view before interacting. Default true. */
  scroll?: boolean;
  /** Simulate keystrokes one char at a time (slow, more compatible). Default false. */
  keystrokes?: boolean;
  /** Per-keystroke delay in ms when keystrokes = true. Default 12. */
  keystrokeDelayMs?: number;
  /** Timeout waiting for the element to become interactable. Default 2000. */
  timeoutMs?: number;
}

export function fillValue(
  targetId: string,
  value: string,
  options?: FillOptions,
): Promise<ActionResult>;

export function clearValue(targetId: string, options?: FillOptions): Promise<ActionResult>;
```

Both are `async`, never throw, and return an `ActionResult` from `@vfe/protocol` (`ok: false` + `error.code` on failure). Internally they share `withElement(targetId, fn)` which resolves via `findByVfeId` (A-1) and applies the interaction prologue.

## Interaction prologue (shared with B-2)

```ts
async function withElement<T>(
  targetId: string,
  fn: (el: HTMLElement) => Promise<T>,
  opts: { scroll?: boolean; timeoutMs?: number } = {},
): Promise<ActionResult> {
  const el = findByVfeId(targetId);
  if (!el) return fail(targetId, 'ELEMENT_NOT_FOUND');
  if (isDisabled(el)) return fail(targetId, 'ELEMENT_DISABLED');

  if (opts.scroll !== false) {
    el.scrollIntoView({ behavior: 'smooth', block: 'center', inline: 'nearest' });
    await waitForInViewport(el, opts.timeoutMs ?? 2000);
  }
  el.focus({ preventScroll: true });
  dispatch(el, 'focus');          // non-bubbling, for React onFocus
  dispatch(el, 'focusin');        // bubbling
  ...
}
```

`waitForInViewport` polls `getBoundingClientRect()` once per animation frame until the centre is inside the viewport or the timeout elapses (smooth scrolling is asynchronous; filling mid-scroll clicks the wrong element on some libs).

## FILL algorithm (exact order — do not reorder)

1. Resolve element via `[data-vfe-id="${CSS.escape(targetId)}"]`.
2. Bail if `disabled`/`readOnly` → `ELEMENT_DISABLED`.
3. `scrollIntoView` + wait for viewport (above).
4. `el.focus({ preventScroll: true })`; dispatch `focus`, `focusin`.
5. Select existing content (`el.setSelectionRange(0, el.value.length)` for text inputs) so autocomplete widgets reset.
6. **Native setter bypass:**

```ts
const proto =
  el instanceof HTMLTextAreaElement ? HTMLTextAreaElement.prototype
  : el instanceof HTMLSelectElement ? HTMLSelectElement.prototype
  : HTMLInputElement.prototype;

const descriptor = Object.getOwnPropertyDescriptor(proto, 'value');
const nativeSetter = descriptor?.set;
if (nativeSetter) nativeSetter.call(el, value);
else (el as HTMLInputElement).value = value; // last resort
```

   Why it works: React installs its own `value` setter on the *instance* (via `Object.defineProperty`) that records the new value in `_valueTracker`. Calling the **prototype** setter bypasses the tracker, so React compares its cached value against the real DOM value on the next event and sees a change → `onChange` fires.
   If the tracker still suppresses the event (React ≥ 17 edge cases), perform the documented **tracker reset**:
```ts
const tracker = (el as any)._valueTracker;
if (tracker) tracker.setValue(''); // force a perceived change
```
   (Guard with a try/catch and only when `process.env.NODE_ENV !== 'production'`? No — production needs it too. Just wrap in try/catch.)
7. **Event sequence** — every event constructed with `{ bubbles: true, cancelable: true, composed: true }` so it crosses shadow boundaries:

| # | Event | Notes |
| - | --- | --- |
| 1 | `beforeinput` (`InputEvent`, `inputType: 'insertText'`, `data: value`) | Required by many rich editors and some validators |
| 2 | `keydown` (`key: 'Unidentified'`) | Some widgets only enable themselves on keydown |
| 3 | `input` (`InputEvent`, `data: value`, `inputType: 'insertText'`) | The critical one for React/Vue/Svelte |
| 4 | `keyup` | |
| 5 | `change` | Fires `onChange` in React for text fields (>16.9) and native validators |
| 6 | `blur` (after a 0 ms `await`) then `focusout` | Only if `options.blur !== false` — many validators run on blur |

   Note: do **not** dispatch `keypress` — it is deprecated and React 19 removes its handling; the blueprint's list includes it, and we deliberately drop it and document why in the README. (If a target site is proven to need it, re-add behind `options.legacyKeypress`.)
8. `await nextFrame()` after `change` so synchronous framework re-renders settle before we return.
9. Post-conditions (verified before returning `ok: true` — this is what makes failures visible instead of silent):

```ts
assertValueApplied(el, value);        // trimmed comparison for text, exact for date/number
assertNoNewValidationError(el);       // optional: report as warning, not failure
```

   `assertValueApplied` failure → `ActionResult { ok: false, error: { code: 'VALUE_MISMATCH' } }` with `details: { expected, actual }`.

### `value` normalisation before writing

| Input `type` | Normalisation |
| --- | --- |
| `email` | trim, lowercase domain only, strip spaces; reject internal spaces → `VALUE_INVALID` |
| `number` | accept `"1,234.50"`/`"1200"` → `"1234.5"`; reject non-numeric → `VALUE_INVALID` |
| `tel` | strip `()-.` and spaces, keep leading `+` |
| `date` | accept `YYYY-MM-DD` only; if given `MM/DD/YYYY` convert; else `VALUE_INVALID` |
| `time` | `HH:MM` 24h |
| `url` | prepend `https://` when missing a scheme |
| `text/textarea` | insert as-is (never trim — user may type spaces deliberately) |
| `password` | insert as-is; never echo in logs/telemetry |

Normalisation lives in `hands/normalise.ts` and is **also** exported for the testbed and for C-2's expectations (single source of truth).

### `keystrokes: true` mode

For widgets that only respond to real per-key events (some IMEs, masked-input libraries):
- clear the field, then for each char: native setter to the prefix, dispatch `keydown`/`input`/`keyup` (`data: char`, `inputType: 'insertText'`), `await sleep(delay)`.
- Budget: cap at 200 chars (throw `VALUE_INVALID` beyond that with a clear message) and cap total time at 5 s.
- Never used by default (too slow for a 40-field form).

## CLEAR algorithm

1. Same prologue.
2. Focus + select-all.
3. Native-setter `value = ''` (inputs/textarea) or `textContent = ''` (contenteditable, after `selectAll`).
4. Dispatch `beforeinput` (`inputType: 'deleteContentBackward'`), `input`, `change`, `keyup`.
5. For `select`: reset `selectedIndex = -1` then dispatch `input` + `change`.
6. For `checkbox`/`radio`: `CLEAR` means unchecked → delegate to `SET_CHECKED(false)` (B-2) and document the aliasing.
7. Post-condition: value `''` (or `-1` for select) → else `VALUE_MISMATCH`.

## contenteditable

```ts
el.focus();
document.execCommand('selectAll', false);
document.execCommand('insertText', false, value);
if ((el.innerText ?? '').trim() !== value.trim()) {
  // fallback for browsers/sites that strip execCommand: manual selection + InputEvent
  const range = document.createRange(); range.selectNodeContents(el);
  const sel = getSelection(); sel?.removeAllRanges(); sel?.addRange(range);
  dispatch(el, 'beforeinput', { inputType: 'insertReplacementText', data: value });
  el.textContent = value;
  dispatch(el, 'input', { inputType: 'insertText', data: value });
}
```

`execCommand` is deprecated but remains the only broadly-working path for rich editors (ProseMirror/Slate/Draft.js rely on `beforeinput`). Document the deprecation and the fallback.

## Edge cases

| Case | Behaviour |
| --- | --- |
| `readOnly` | `ELEMENT_DISABLED` with details `{ readOnly: true }` |
| `maxLength` shorter than value | Truncate and add warning `MAXLENGTH_TRUNCATED`; do not fail |
| Masked input (phone) | Set the raw digits; if the mask rejects, retry once with the masked format; else `VALUE_INVALID` |
| `<input type=file>` | `ELEMENT_NOT_FILLABLE` (never attempt) |
| Element re-rendered between resolve and write | Re-resolve once via `findByVfeId`; if still missing → `ELEMENT_NOT_FOUND` |
| Autocomplete dropdown opens and overlays | After fill, dispatch `Escape` keydown to dismiss suggestions (config `dismissAutocomplete: true`, default true) |
| `beforeinput` preventDefault'd | Respect it: if `input` did not land, fall back to `keystrokes: true` once, then fail `VALUE_MISMATCH` |

## Test plan

`packages/dom-engine/test/browser/fill/*.spec.ts`, testbed routes:

| Route | Assertion |
| --- | --- |
| `/react-controlled` | React state reflects the value: the page renders `state.firstName` back into a `<pre>` and a submit button dumps JSON; after `fillValue` the dumped JSON contains the value **without** any human typing |
| `/react-controlled` + `onBlur` validation | blur fires validation exactly once |
| `/vue-vmodel` | `v-model` bound value updates |
| `/svelte-bind` | bound value updates |
| `/angular-reactive` | `ngModel`/`FormControl` value updates |
| `/masked-phone` | masked input contains formatted value |
| `/richtext-tiptap` | contenteditable receives the text and the editor's model updates |
| `/uncontrolled` | plain DOM value set |
| `/react-strict-mode` | works in React 18 StrictMode (double-invoked effects) |
| `/form-reset` | after fill, a subsequent `clearValue` leaves framework state empty (proves the setter hack, not just the DOM) |

Each spec also asserts `ActionResult.ok === true` and that no console errors were produced.

### Unit (jsdom)

- Event sequence exactly matches the table above (spy on `dispatchEvent`, assert `inputType`/`data`/`composed`).
- Every normaliser branch (table-driven).
- `ELEMENT_NOT_FOUND`, `ELEMENT_DISABLED`, `VALUE_MISMATCH` paths.
- `keystrokes: true` emits one event triple per char and respects the delay (fake timers).
- `maxLength` truncation warning.
- `CLEAR` on input/textarea/select/contenteditable.

## Acceptance criteria

- [ ] Tested against a controlled React `<input value={state} onChange={…} />`: `FILL` updates React state without human keystrokes (asserted through a rendered JSON dump, not `el.value`).
- [ ] Same proven for Vue `v-model`, Svelte `bind:value`, and Angular `ngModel`.
- [ ] `el.value` also reflects the value (DOM and framework state agree).
- [ ] Events are `bubbles: true, composed: true` and `input` is a real `InputEvent` with `inputType` set.
- [ ] Never throws; always returns `ActionResult`; failures carry a specific `ActionErrorCode`.
- [ ] `VALUE_MISMATCH` is returned when a site rejects the value (detected, not assumed).
- [ ] Passwords are never logged (assert no `console` call contains the value; no telemetry in MVP).
- [ ] `contenteditable` works on the TipTap testbed route.
- [ ] 40-field fill completes in < 6 s with default options (no `keystrokes`).
- [ ] No `document.execCommand` usage outside the contenteditable module (lint rule / code review).

## Non-goals

- File uploads.
- `<iframe>`/cross-origin contenteditable.
- Simulating a full IME composition session (`compositionstart`/`compositionend`); `keystrokes` mode is the documented approximation.
- Undo/redo stack integration.
