## Summary

The "Hands", part 2: every non-text interaction. Native `<select>`s, ARIA comboboxes (Radix/Headless UI/MUI), checkboxes and radios (including the visually-hidden native input behind a styled label), buttons in SPA frameworks, focus management, and scrolling.

The hard part is not `click()` — it is that a large fraction of modern UI libraries ignore synthetic `.click()` and listen on `pointerdown`, or require a trusted-ish event sequence, or open a portal that must be re-distilled before the option exists.

## Public API

```ts
// packages/dom-engine/src/hands/controls.ts
export function selectOption(targetId: string, value: string, opts?: ControlOptions): Promise<ActionResult>;
export function setChecked(targetId: string, checked: boolean, opts?: ControlOptions): Promise<ActionResult>;
export function clickElement(targetId: string, opts?: ControlOptions): Promise<ActionResult>;
export function focusElement(targetId: string, opts?: ControlOptions): Promise<ActionResult>;
export function scrollPage(direction: 'up' | 'down' | 'top' | 'bottom', opts?: ScrollOptions): Promise<ActionResult>;

export interface ControlOptions {
  scroll?: boolean;
  timeoutMs?: number;
  /** For SELECT: if the option list is not open, open it and wait this long. Default 800. */
  openTimeoutMs?: number;
}
```

All return `ActionResult` (never throw). Shared prologue (`withElement`) from B-1.

## SELECT

### Native `<select>`

1. Resolve element; bail if `disabled` → `ELEMENT_DISABLED`.
2. `el.focus()` + `focus`, `focusin` events.
3. **Option matching waterfall** (first hit wins):
   1. exact `option.value === value`;
   2. case-insensitive `option.value.toLowerCase() === value.toLowerCase()`;
   3. exact trimmed `option.text === value`;
   4. case-insensitive text match;
   5. normalised text match (strip punctuation/whitespace: `"United States"` ↔ `"united states"`, `"U.S.A."` ↔ `"usa"`);
   6. prefix match (text starts with value, length ≥ 3, exactly one candidate);
   7. substring match (exactly one candidate);
   8. Levenshtein ≤ 2 among text candidates with a unique best match.
4. If zero candidates → `OPTION_NOT_FOUND` with `details.available = optionTexts.slice(0, 20)` **so the Brain can retry with a valid option** (surfaced by INT-2).
5. If multiple candidates at the last step → `OPTION_NOT_FOUND` with `details.ambiguous = [...]` (never guess).
6. Apply: use the native setter (`HTMLSelectElement.prototype.value`) then `selectedIndex` fallback; dispatch `input` (`InputEvent`) then `change` (both `bubbles: true, composed: true`), plus `focus`/`blur` per B-1 ordering.
7. Post-condition: `el.value === matchedOption.value` else `VALUE_MISMATCH`.

Multiple-select: if `el.multiple`, `SELECT` adds the matched option to the selection (`option.selected = true`) and dispatches `input`/`change`; `CLEAR` clears all. Document that only one option can be selected per action (the Brain can emit several `SELECT`s).

### ARIA combobox / `role="listbox"` (Radix, Headless UI, MUI, Downshift, react-select)

Deterministic state machine; **never** blind-append options:

```
S0 check: is a listbox for this combobox already open?
   → yes: skip to S2
S1 open: clickElement(combobox)  (full pointer sequence)
   → wait for [role="listbox"] to appear (MutationObserver + rAF poll, openTimeoutMs)
   → if it never appears: fall back to typing (see S1b)
S1b typeahead fallback (only if options === [] after open):
   fillValue(combobox, valuePrefix) ; wait 150 ms ; re-scan
S2 read options: the closest visible [role="listbox"] (portal-aware: document-wide search,
   preferring one whose aria-controls/aria-owns points at the combobox, else the last one opened)
S3 match: same waterfall as native (text-first, because ARIA options often have generated values)
S4 click the option: full pointer sequence (options are usually <li role="option"> handling pointerdown)
S5 verify: combobox aria-expanded === 'false' AND
   (combobox text contains the option text OR combobox aria-activedescendant/value reflects it)
   → else return VALUE_MISMATCH with details.optionClicked = true
```

Key requirements:
- Option elements must be read **after** opening; the snapshot the Brain used may be stale. This is exactly the `CLICK`-first protocol C-1 implements: the Brain may emit `CLICK` then a second command does `SELECT`.
- If the combobox is a real `<input>` with `role="combobox"` (Downshift/MUI Autocomplete), typeahead + `ArrowDown`+`Enter` is more reliable than clicking rendered options:
  1. `fillValue(el, value)`, wait 200 ms;
  2. if `[role=option]` appears, click the best match (S3/S4);
  3. else press `ArrowDown`, `Enter` via `KeyboardEvent` dispatch on the input.
- Close-open mismatch guard: if after `openTimeoutMs` the listbox is absent, dispatch `Escape` to reset and return `TIMEOUT` (the Brain can then `ASK_CLARIFICATION`).

## SET_CHECKED

1. Resolve; determine current state:
   - native: `(el as HTMLInputElement).checked`;
   - ARIA: `aria-checked === 'true'` (also handle `mixed` → treat as `false` for target `true`).
2. If `current === checked` → return `ok: true` with `warnings: ['NO_OP']` (idempotent; never toggle twice).
3. **Choose the click target** — this is the part that breaks naive implementations:
   - Compute `proxy = <label for=el.id>` **or** `el.closest('label')` **or** `[data-testid][aria-labelledby~=el.id]`.
   - If the element itself is visible and has a non-zero rect → click the element.
   - Else if a proxy exists → click the proxy (with the full pointer sequence).
   - Else → set `checked` via the native setter and dispatch `click`? No: dispatch `input` + `change` with `target.checked` already flipped via the native setter (last resort, no `click` event fidelity).
4. Radios: clicking a radio that is already checked is a **no-op in the DOM** and will *not* fire `change`; guard by comparing `checked` first (step 2). For a group, the Brain emits one `SET_CHECKED` per radio it wants.
5. Post-condition: re-read state; mismatch → `VALUE_MISMATCH`.

## CLICK

Full pointer sequence at the element's visual centre — required for Radix/Headless UI, which listen on `pointerdown`:

```ts
const r = el.getBoundingClientRect();
const x = r.left + r.width / 2;
const y = r.top + r.height / 2;
const base = { bubbles: true, cancelable: true, composed: true, clientX: x, clientY: y, button: 0, buttons: 0 };

el.dispatchEvent(new PointerEvent('pointerover', base));
el.dispatchEvent(new PointerEvent('pointerenter', { ...base, bubbles: false }));
el.dispatchEvent(new PointerEvent('pointerdown', { ...base, buttons: 1, pressure: 0.5, pointerType: 'mouse', isPrimary: true }));
el.dispatchEvent(new MouseEvent('mousedown', { ...base, buttons: 1, detail: 1 }));
el.focus({ preventScroll: true });
el.dispatchEvent(new PointerEvent('pointerup', base));
el.dispatchEvent(new MouseEvent('mouseup', { ...base, detail: 1 }));
el.dispatchEvent(new MouseEvent('click', { ...base, detail: 1 }));
```

- `PointerEvent` may be missing in jsdom → feature-detect and fall back to `MouseEvent` (tests rely on this; browsers all have it).
- If the element is 0-size or `pointer-events: none`, click its nearest ancestor with a box, or its label.
- **Navigation guard:** if the click causes a page navigation (`beforeunload`/`pagehide` or an SPA route change within 300 ms), the executor must not wait for the page — `INT-1` handles teardown. B-2 returns `ok: true` with `warnings: ['NAVIGATION']`.
- Never click elements matched by `a[href^="javascript:"]` unless the Brain's target explicitly resolves to them (XSS hygiene).

## FOCUS

`el.focus({ preventScroll: false })` + `focus`/`focusin`/`focusout`(on previous) events; verify `activeElement` (crossing shadow roots) → else `ELEMENT_NOT_FOUND` with `details.activeElement`.

## SCROLL

- `up` / `down`: `window.scrollBy({ top: ±0.8 * innerHeight, behavior: 'smooth' })`.
- `top` / `bottom`: `scrollTo(0, 0 | document.body.scrollHeight)`.
- If the page has a scroll container (`overflow: auto|scroll` element taller than the viewport containing most interactives), scroll that container instead — detect once by finding the element with the largest `scrollHeight - clientHeight` among `[style*="overflow"], main, [role=main], .content` candidates.
- Returns after `scrollend` or 400 ms fallback. Re-distillation is INT-1's job, not B-2's.

## Dispatch helper (shared)

```ts
export function dispatch(el: Element, type: string, init?: EventInit & Record<string, unknown>): boolean {
  const Ctor = EVENT_CTORS[type] ?? Event;   // InputEvent, KeyboardEvent, PointerEvent, MouseEvent, FocusEvent
  return el.dispatchEvent(new Ctor(type, { bubbles: true, cancelable: true, composed: true, ...init }));
}
```

One helper, used by B-1 and B-2, so event construction never drifts between tickets.

## Acceptance criteria

- [ ] Native `<select>` selection by value, exact text, case-insensitive, normalised (`"United States"`), prefix, and fuzzy match.
- [ ] Radix/Headless UI/MUI custom dropdowns open and select correctly (Playwright against the testbed).
- [ ] Custom dropdown that ignores `.click()` works because the full pointer sequence is dispatched.
- [ ] Visually hidden checkbox toggles via its label proxy.
- [ ] `SET_CHECKED` is idempotent and never double-toggles (explicit regression test).
- [ ] Radio group selection unchecks siblings and fires exactly one `change`.
- [ ] `CLICK` works on SPA links/buttons and reports `NAVIGATION` when the page changes.
- [ ] `SCROLL` handles window and nested containers, all four directions.
- [ ] Zero throws across all paths; every failure is a typed `ActionResult`.
- [ ] `OPTION_NOT_FOUND` always includes available/ambiguous details for retry.

## Non-goals

- `<input type=range>`/`<input type=color>` precise manipulation by voice (documented limitation; `FILL` writes the value and dispatches `input`, which is enough for most).
- Drag & drop, sliders built on `draggable`.
- Keyboard-only shortcuts / focus traps.
- Multi-select-by-voice ("select red, green and blue in one action") — Brain emits one `SELECT` per option.
