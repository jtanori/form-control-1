## Summary

The "Ears", part 1: capture the microphone, detect speech reliably, and hand a clean PCM/WAV buffer to the STT client — inside a Chrome Manifest V3 extension where the background **service worker cannot access the microphone at all**.

This ticket covers the capture architecture, VAD integration, permission flow, and the event contract to the rest of the extension. No network calls to STT here (D-2).

## The MV3 constraint (read this first)

| Context | `getUserMedia` | Notes |
| --- | --- | --- |
| Content script (isolated world, page tab) | ✅ yes | Permission prompt appears for the **page's origin**, and is remembered per-origin — a terrible UX on every new site. |
| Extension service worker | ❌ no | No DOM, no `MediaDevices`. |
| Offscreen document | ✅ yes | `chrome.offscreen` DOM context with the **extension's** origin → one permission covers all sites. |
| Popup / options page | ✅ yes | Extension origin too, but closes when the user clicks away. |

**Decision: Offscreen Document is the audio host.** Content script (or the HUD) sends `AUDIO_START`/`AUDIO_STOP` messages; the SW ensures the offscreen doc exists (`chrome.offscreen.createDocument({ reasons: ['USER_MEDIA'], justification: 'Voice input for form filling' })` — `USER_MEDIA` is the correct reason), forwards the commands, and relays `VAD_*` events back.

Fallback (documented, feature-flagged): if `chrome.offscreen` is unavailable (very old Chromium forks), capture in the content script after a popup-driven `getUserMedia` grant.

### Permission flow

1. Popup "Enable microphone" button → `chrome.storage.local.set({ micEnabled: true })` **after** the offscreen doc has successfully opened a `getUserMedia` stream at least once (this is the only way to trigger the browser permission prompt in a UI the user expects).
2. Content script never calls `getUserMedia`.
3. If permission is later revoked/denied, the offscreen doc emits `AUDIO_ERROR { code: 'NOT_ALLOWED' }` and the SW caches `micEnabled: false`; the HUD (E-1) shows a "Grant microphone access" state instead of failing silently.
4. `chrome.permissions` is **not** needed for mic in an extension page, but the manifest must declare nothing extra beyond `custom content script` defaults; the offscreen doc requires no manifest entry in MV3 (only `offscreen` permission).

## Public event contract (extension-internal, `packages/extension/src/messaging.ts`)

```ts
export type AudioEvent =
  | { type: 'AUDIO_READY' }
  | { type: 'AUDIO_ERROR'; code: 'NOT_ALLOWED' | 'NO_DEVICE' | 'DEVICE_BUSY' | 'UNSUPPORTED' | 'VAD_INIT_FAILED' | 'OFFSCREEN_FAILED'; message: string }
  | { type: 'VAD_SPEECH_START'; at: number }
  | { type: 'VAD_SPEECH_END'; at: number; durationMs: number; audio: ArrayBuffer /* 16 kHz mono PCM16 WAV */ }
  | { type: 'VAD_MISFIRE'; rmsDb: number }            // detected then discarded as noise
  | { type: 'LISTENING_STATE'; listening: boolean; mutedForTts: boolean };

// content ⇄ SW ⇄ offscreen commands
export type AudioCommand =
  | { type: 'AUDIO_START' }        // begin VAD loop
  | { type: 'AUDIO_STOP' }         // stop + release stream
  | { type: 'AUDIO_MUTE' }         // pause detection while TTS speaks (D-2)
  | { type: 'AUDIO_UNMUTE' };
```

All message payloads are validated with zod locally (not in `@vfe/protocol` — this is extension-internal, see P0-2 non-goals). Never trust `sender` — verify `sender.id === chrome.runtime.id` in the SW.

## VAD specification

Use `@ricky0123/vad-web` (Silero v5 ONNX via `onnxruntime-web`), **not** a hand-rolled RMS gate. Configure:

```ts
const vad = await MicVAD.new({
  model: 'v5',
  baseAssetPath: chrome.runtime.getURL('vad/'),
  onnxWASMBasePath: chrome.runtime.getURL('vad/'),
  positiveSpeechThreshold: 0.5,      // default 0.5; tune per device
  negativeSpeechThreshold: 0.35,
  redemptionMs: 600,                 // ← the blueprint's "> 600 ms pause end" rule
  preSpeechPadMs: 300,               // don't clip the first syllable
  minSpeechMs: 300,                  // ignore clicks/coughs
  submitUserSpeechOnPause: true,
  onSpeechStart: () => emit({ type: 'VAD_SPEECH_START', at: Date.now() }),
  onSpeechEnd: (audio /* Float32Array @16kHz */) => {
    const wav = encodeWavPcm16(audio, 16000);
    emit({ type: 'VAD_SPEECH_END', at: Date.now(), durationMs: audio.length / 16, audio: wav.buffer });
  },
  onVADMisfire: () => emit({ type: 'VAD_MISFIRE', rmsDb: rms(audio) }),
});
```

Requirements:
- `encodeWavPcm16` must be a **pure, unit-tested** function (`packages/extension/src/audio/wav.ts`): 44-byte RIFF header, mono, 16 kHz, 16-bit PCM, correct `data` chunk size and byte rate. Snapshot-test the header bytes.
- Sample rate: request `{ audio: { channelCount: 1, echoCancellation: true, noiseSuppression: true, autoGainControl: true, sampleRate: 16000 } }`; if the device ignores `sampleRate`, resample using an `OfflineAudioContext` (16 kHz target) before encoding — Whisper wants 16 kHz and the provider charges by duration.
- Max utterance: 30 s (force `VAD_SPEECH_END` and stop listening to bound cost/latency); min 300 ms (else `VAD_MISFIRE`).
- **Do not** keep the stream open forever: after 60 s of continuous listening with no speech, stop and emit `LISTENING_STATE { listening: false }` (battery + privacy). The user re-activates with Alt+V.
- Echo/self-voice: while TTS is speaking, `AUDIO_MUTE` must pause VAD (`vad.pause()`), and `AUDIO_UNMUTE` resume *after* a 250 ms tail (D-2 calls these).
- Only one offscreen document may exist; the SW must guard creation with a single in-flight promise (a well-known MV3 race — `chrome.offscreen.hasDocument()` + a module-level lock).
- The offscreen doc must be closed when listening stops for > 5 min (`chrome.offscreen.closeDocument()`) to release the mic indicator.

## Privacy requirements (non-negotiable)

- Audio is processed **in memory only**: never written to `chrome.storage`, IndexedDB, or the filesystem; dropped immediately after `VAD_SPEECH_END` is consumed by D-2.
- The content script never receives raw audio (it doesn't need it) — `VAD_SPEECH_END.audio` is routed **only** to the SW/offscreen → D-2. Add a test that the content-script message handler rejects a payload containing `audio`.
- The mic indicator must be visible whenever listening (the HUD pill shows `LISTENING`), and stopping must actually stop the track (`stream.getTracks().forEach(t => t.stop())`), verified by asserting `track.readyState === 'ended'`.
- `host_permissions: <all_urls>` is an MVP concession; document it in the store listing and the README, and note the Phase-2 plan (optional permissions / activeTab-only injection).

## Test plan

### Unit (jsdom, mocked `chrome.*`)

- `encodeWavPcm16`: header fields (`RIFF`, `WAVE`, `fmt `, PCM=1, channels=1, 16000, bits=16), `data` size, byte rate `32000`; empty input → header only; odd sample counts handled.
- `resample`: 44.1 kHz sine → 16 kHz, length ratio correct, no NaN.
- Offscreen manager: two concurrent `AUDIO_START`s create **one** document (single-flight lock test).
- Message router: rejects senders whose `sender.id` differs; rejects unknown message types; rejects `audio` in a content-script → HUD path.
- State machine: `AUDIO_STOP` releases the track and closes the doc after the idle timer (fake timers).

### Playwright (real Chromium + fake audio device)

Launch Chromium with `--use-fake-ui-for-media-stream --use-fake-device-for-media-stream --use-file-for-fake-audio-capture=<fixture.wav>`:

| Test | Assertion |
| --- | --- |
| `speech-end-fired` | 1.5 s of speech then silence → exactly one `VAD_SPEECH_END` with `durationMs` within ±200 ms |
| `noise-ignored` | silence + keyboard clicks fixture → no `VAD_SPEECH_END`, no misfire storm |
| `misfire` | 100 ms burst → `VAD_MISFIRE`, no transcription |
| `redemption-600` | two utterances 400 ms apart are **one** event; 900 ms apart are two |
| `mute-during-tts` | `AUDIO_MUTE` → no speech events until unmuted |
| `max-duration` | 35 s speech → cut at 30 s |
| `stop-releases-mic` | after `AUDIO_STOP`, `track.readyState === 'ended'` and the tab shows no mic indicator |

## Acceptance criteria

- [ ] Microphone works from the extension origin (offscreen document), **not** per-site content scripts — one permission for all sites.
- [ ] Speaking reliably fires `VAD_SPEECH_START` then `VAD_SPEECH_END` with a valid 16 kHz mono PCM16 WAV buffer.
- [ ] Background noise, typing clicks, and < 300 ms bursts do not produce transcripts (`VAD_MISFIRE` instead).
- [ ] A 600 ms pause ends the utterance; a 400 ms pause does not.
- [ ] `AUDIO_MUTE`/`AUDIO_UNMUTE` pause detection for TTS.
- [ ] Utterances capped at 30 s; listening auto-stops after 60 s of silence.
- [ ] Mic track is released on stop; no offscreen document left behind after the idle timeout.
- [ ] Only one offscreen document ever exists (race guarded and tested).
- [ ] WAV encoder unit-tested against a byte-level snapshot.
- [ ] No audio persisted anywhere (assert `chrome.storage` untouched; code review).
- [ ] `Alt+V` command is registered and toggles listening.

## Non-goals

- Wake-word / always-listening mode (privacy and battery).
- Streaming STT (`MediaRecorder` chunks) — D-2 does one-shot transcription per utterance; streaming is a Phase-2 ticket.
- Echo cancellation beyond the browser's defaults.
- Firefox/Safari (MV3 `offscreen` is Chromium-only).
