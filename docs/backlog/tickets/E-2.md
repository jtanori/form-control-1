## Summary

The badges are what make voice referencing possible: every discovered control gets a visible number, so the user can say _"put 90210 in field 4"_ instead of describing a field. The overlay must stay **exactly** glued to its input while the user scrolls, resizes, opens accordions, or the page re-renders — at 60 fps, with no layout thrash.

## Rendering architecture

- One `<vfe-badges>` host element, `position: fixed; inset: 0; pointer-events: none; z-index: 2147483646` (one below the HUD pill), containing a **single** shadow root.
- **One absolutely-positioned `<div class="vfe-badge">` per element**, created once per `vfeId` and mutated thereafter — never re-created on scroll (re-creating nodes on every frame is the classic way to miss 60 fps).
- Positioned with `transform: translate3d(x, y, 0)` only (compositor-friendly; no `top/left` writes → no layout).
- `will-change: transform` on badges is **deliberately avoided** for > 50 badges (memory), applied only while `isRepositioning` is true.

### Positioning algorithm

```ts
function positionBadges(list: Array<{ el: HTMLElement; node: HTMLElement }>) {
  const vw = window.innerWidth,
    vh = window.innerHeight;
  const scrollX = window.scrollX,
    scrollY = window.scrollY;
  for (const { el, node } of list) {
    const r = el.getBoundingClientRect(); // read phase only
    const offscreen = r.bottom < 0 || r.top > vh || r.right < 0 || r.left > vw;
    const hidden = r.width === 0 && r.height === 0;
    node.style.visibility = offscreen || hidden ? 'hidden' : 'visible';
    if (offscreen || hidden) continue; // skip transform writes
    const x = clamp(r.left + scrollX - 10, scrollX + 2, scrollX + vw - 22); // top-left, nudged outside the input
    const y = clamp(r.top + scrollY - 10, scrollY + 2, scrollY + vh - 22);
    node.style.transform = `translate3d(${x}px, ${y}px, 0)`;
  }
}
```

Because the host is `position: fixed` with `inset: 0` and the badges are positioned in **document coordinates** translated inside it, no `scroll` listener is needed for the common case — but fixed positioning + document coordinates is _not_ equivalent under CSS transforms on ancestors, so:

**Two modes, chosen once at mount:**

1. **`scroll-listener` mode (default)**: host is `position: fixed`; badges are positioned with **viewport coordinates** (`r.left`, `r.top`); reposition on `scroll` (capture phase, `passive: true`) and `resize`, throttled to one pass per animation frame.
2. **`no-listener` mode**: used when the page has no scroll (common in SPAs) — position once, re-check every 1000 ms.

`scroll` listeners must use `{ passive: true, capture: true }` to catch scrolling inside nested containers, and the reposition pass must be coalesced:

```ts
let scheduled = false;
function scheduleReposition() {
  if (scheduled) return;
  scheduled = true;
  requestAnimationFrame(() => {
    scheduled = false;
    positionBadges(list);
  });
}
```

Additionally reposition on: `wheel` (throttled 100 ms), `keydown` (focus moves), `focusin` (input got focus → highlight), `transitionend`/`animationend` on the page (accordions), and every distilled state change.

### Badge visual spec

- 20×20 px, `border-radius: 999px`, `background: #111827`, `color: #fff`, `font: 600 11px/20px system-ui`, `box-shadow: 0 1px 2px rgba(0,0,0,.4), 0 0 0 1.5px #fff` (white ring keeps it visible on dark inputs).
- Content is the `badgeIndex` number — **not** the `vfeId`.
- States: `default`, `active` (green `#22c55e`, scale 1.15, only while `onActionStart` fires for its id), `disabled` (grey, 55% opacity, `aria-disabled`), `error` (red ring, when the element has a `validationError`), `focused` (blue ring).
- `pointer-events: none` on the overlay **and** the badge in MVP (clicking a badge to target a field is a nice-to-have; enabling it would steal clicks from the host page — document as Phase 2).
- `data-badge-index` and `data-vfe-id` attributes on the badge node for tests.

### Sync contract with the DOM engine

```ts
export interface BadgeController {
  /** Replace the full badge set from a distilled page state. */
  sync(pageState: PageState): void;
  /** Momentarily highlight a badge (green) — driven by B-3's onActionStart. */
  flash(vfeId: string, result?: 'ok' | 'error'): void;
  /** Pause all repositioning (e.g. while the tab is hidden). */
  setEnabled(enabled: boolean): void;
  destroy(): void;
}

export function mountBadges(): BadgeController;
```

- `sync()` diffs by `vfeId`: create new nodes, remove stale ones, update numbers when `badgeIndex` changed, and **never** touch the DOM when the diff is empty (this is the hot path during `watchPage` bursts).
- Elements are resolved from `data-vfe-id` **at render time** via A-1's `findByVfeId` (elements are replaced by React; holding `HTMLElement` references forever leaks memory and points at detached nodes). Keep a `WeakMap` cache and re-resolve on each `sync()`.
- Node budget: hard cap at 250 badges (matches A-1); above 60 badges, apply `contain: strict` and skip `box-shadow` for performance.
- Accessibility: `aria-hidden="true"` on the badge text (the numbers are redundant with the labels the screen reader announces) BUT the HUD announces "Field 4" on request; the overlay itself must be invisible to the a11y tree.

### Performance requirements

| Scenario                                   | Budget                                    |
| ------------------------------------------ | ----------------------------------------- |
| Initial render of 100 badges               | < 30 ms                                   |
| Reposition pass, 100 badges, per frame     | < 4 ms on a mid-tier laptop               |
| Scroll for 5 s at 60 fps with 100 badges   | zero long tasks > 50 ms, ≥ 55 fps average |
| 10 rapid `sync()` calls (re-distill burst) | < 40 ms total, no badge flicker           |

Implementation rules that make this achievable:

- One `requestAnimationFrame` per frame max (a single shared scheduler).
- **Read-then-write**: collect all rects in one loop, then apply transforms in a second loop (avoid layout thrash).
- Never read `offsetWidth`/`innerText` in the hot path.
- `document.hidden` → skip all work; on `visibilitychange` → one immediate reposition.
- `ResizeObserver` on the page's scroll container(s) (optional, only if `scroll-listener` mode proves insufficient) with a 200 ms debounce.

## Edge cases

| Case                                                                        | Behaviour                                                                                             |
| --------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| Element inside a transformed ancestor (`transform: scale`)                  | `getBoundingClientRect()` already accounts for it — badges stay correct.                              |
| Element inside an open shadow root                                          | Positioned via `getBoundingClientRect()` — correct, because badges live in a top-level fixed overlay. |
| Element inside a fixed-position modal                                       | Correct in viewport coordinates.                                                                      |
| Zoom / devicePixelRatio                                                     | `getBoundingClientRect()` is in CSS px; no special handling.                                          |
| Host page scrolls an inner container                                        | `scroll` capture listener catches it.                                                                 |
| Host page uses `document.body { overflow: hidden }` scroll jail on `<html>` | Capture listener on `document` covers both.                                                           |
| Page removes our host element                                               | Remount guard (same as E-1).                                                                          |
| > 250 elements                                                              | Only the first 250 are badged (consistent with the Brain's `maxElements`).                            |
| Badge would render off the left/top edge                                    | Clamp inside the viewport.                                                                            |
| Element has `pointer-events: none`                                          | Badge still rendered (pure overlay).                                                                  |

## Acceptance criteria

- [ ] Every visible discovered input shows a neat `[1]`, `[2]` badge at its top-left corner.
- [ ] Badges stay glued to their inputs at ≥ 55 fps average during a 5 s scroll on a 100-badge page (measured, not assumed).
- [ ] `sync()` performs zero DOM writes when the page state is unchanged.
- [ ] Badges are unaffected by host CSS (isolation suite passes) and never steal clicks.
- [ ] Active badge turns green while its action executes (`onActionStart` → `flash`), error badges show a red ring.
- [ ] Numbers always match `PageState.elements[].badgeIndex`.
- [ ] Hard cap of 250 badges enforced.
- [ ] Badge overlay is `aria-hidden` and does not pollute the host's accessibility tree.
- [ ] `destroy()` removes every node and listener; repeated mount/sync/destroy cycles do not leak (heap snapshot smoke test).
- [ ] Zero layout thrash: reads and writes are separated (verified by a `getBoundingClientRect` spy ordering test).

## Non-goals

- Clicking a badge to target a field (Phase 2).
- Badges inside iframes or closed shadow roots.
- Tooltips showing the field label.
- Animating badges between states beyond the 150 ms flash.
