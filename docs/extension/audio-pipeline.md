# Audio pipeline (D-1)

## Why an offscreen document

| Context                | Microphone | Permission scope                   |
| ---------------------- | ---------- | ---------------------------------- |
| Service worker (MV3)   | ❌ no DOM  | —                                  |
| Content script         | ✅ yes     | **Per site** — a prompt per origin |
| **Offscreen document** | ✅ yes     | Extension origin — one prompt      |
| Popup                  | ✅ yes     | Closes when focus is lost          |

The service worker cannot call `getUserMedia`, and per-site prompts would make
the product unusable. The offscreen document is the audio host; the SW only
routes messages and owns its lifecycle.

```text
 content script (HUD)                 service worker                 offscreen document
 ────────────────────                 ──────────────                 ──────────────────
 AUDIO_START ───────────────► ensure offscreen (single-flight lock) ──► getUserMedia + MicVAD
                              ◄───────────── AUDIO_READY ───────────────
 VAD_SPEECH_START ◄────────── broadcast (no audio) ◄── onSpeechStart ───
 VAD_SPEECH_END   ✗ never      onSpeechEnd → D-2 STT   ◄── onSpeechEnd ── 16 kHz WAV
 LISTENING_STATE  ◄────────── broadcast ◄──────────────────────────────
 AUDIO_MUTE/UNMUTE ─────────► forward ────────────────────────────────► vad.pause()/resume()
```

## Permission flow

1. The popup's **Enable microphone** button sends `AUDIO_START` through the SW.
2. The SW opens the offscreen document and forwards the command.
3. The offscreen document calls `getUserMedia` → Chrome shows the permission
   prompt for the extension origin.
4. On `AUDIO_READY` the popup stores `micEnabled: true` and stops listening.
5. A denial emits `AUDIO_ERROR { code: 'NOT_ALLOWED' }`; the popup stores
   `micEnabled: false` and the HUD (E-1) shows a grant action. The content
   script never calls `getUserMedia` and never sees an error dialog.

## VAD tuning

Silero v5 via `@ricky0123/vad-web` (ONNX runtime WASM), assets served from
`chrome.runtime.getURL('vad/')` and listed in `web_accessible_resources`.

| Setting                 | Value | Why                                           |
| ----------------------- | ----: | --------------------------------------------- |
| positiveSpeechThreshold |  0.50 | Default; tuned per device later               |
| negativeSpeechThreshold |  0.35 | Hysteresis, avoids clipping soft endings      |
| redemptionMs            |   600 | Blueprint's "600 ms pause ends the utterance" |
| preSpeechPadMs          |   300 | Keeps the first syllable                      |
| minSpeechMs             |   300 | Clicks and coughs become `VAD_MISFIRE`        |
| maxUtteranceMs          |  30 s | Bounds latency and provider cost              |
| silenceAutoStopMs       |  60 s | Battery + privacy; user re-arms with Alt+V    |
| muteTailMs              |   250 | Prevents TTS echo re-triggering the VAD       |

The library cannot flush a partial utterance, so a parallel `PcmCollector`
(ScriptProcessor, zero-gain destination) keeps 35 s of 16 kHz audio. When the
30 s timer fires, the collector is sliced, resampled, encoded and emitted as
`VAD_SPEECH_END { durationMs: 30000 }`, then the session stops and the track is
released. Normal utterances use the library's own 16 kHz buffer.

## Lifecycle guarantees

- `OffscreenManager` acquires its creation lock **synchronously** before any
  `await`; three concurrent `AUDIO_START`s still create exactly one document.
- `AUDIO_STOP` stops every track (`readyState === 'ended'`) and schedules the
  document close 5 minutes later. Starting again cancels the timer.
- Muting pauses the VAD and clears timers; unmuting resumes after 250 ms.
- No speech for 60 s → stop; utterance ≥ 30 s → cut and stop.
- One offscreen document per profile; the SW owns creation and closure.

## Privacy

- Audio exists only in the offscreen document's memory. Nothing is written to
  `chrome.storage`, IndexedDB, Cache Storage or disk.
- `VAD_SPEECH_END` is handled exclusively by the service worker (D-2). The
  router rejects any audio payload that arrives from a content script
  (`AUDIO_IN_CONTENT_PATH`) and never broadcasts one to a tab.
- Logs never contain transcripts or audio.
- `host_permissions: <all_urls>` is an MVP concession for automatic injection;
  the Phase-2 plan is optional permissions plus `activeTab`-only injection. It
  is disclosed in the store listing and this document.

## Testing

```bash
pnpm --filter @vfe/extension test                 # 33 unit tests (jsdom, mocked chrome)
RUN_EXTENSION_E2E=1 \
pnpm --filter @vfe/extension test:e2e:audio       # real Chromium + fake microphone
```

Audio fixtures (`test/fixtures/audio`, 172 KB total) are generated by
`pnpm --filter @vfe/extension fixtures:audio`; Playwright launches Chromium with
`--use-fake-ui-for-media-stream --use-fake-device-for-media-stream
--use-file-for-fake-audio-capture=…`. The `max-duration` cut is covered by the
unit test (fake timers) because a 35 s PCM fixture would exceed the repository
budget.
